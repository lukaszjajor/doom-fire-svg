DOOM fire in SVG

The fire effect from the PlayStation port of DOOM and from Doom 64, reimplemented with nothing but SVG filters and SMIL animation. No JavaScript, no canvas, not a single frame of raster imagery. Each flame below is a standalone file of roughly 3 kB.

Write-up: SVG course at iFox.pl (Polish) · Files: svg/ · License: MIT

Four files, one difference

All four share an identical filter, an identical gradient and an identical animation. They differ by eighteen numbers in feComponentTransfer — six per colour channel. That is the entire palette. 

<feFuncR type="table" tableValues="0 0.16 0.63 0.9 1 1"/>
<feFuncG type="table" tableValues="0 0    0.08 0.43 0.86 1"/>
<feFuncB type="table" tableValues="0 0    0    0    0.24 1"/>

Read them vertically, column by column, and you get the path of heated metal: black, dark red, red, orange, yellow, white. The channel that rises earliest decides the colour of the whole thing.

The historical version

The demo/ directory holds the other implementation — the original one, a pixel buffer recomputed in JavaScript, with a toggle between the DOOM variant (copying with random drift) and the demoscene variant (averaging neighbours). Open the demo — the page is in Polish, but the toggle and sliders speak for themselves.

How it works

A short summary is in the README. The full write-up — from the temperature buffer, through palettes, to three traps of the filter region — is in the lesson, in Polish.

The effect comes from the PlayStation and Nintendo 64 ports of DOOM. The algorithm was reconstructed by Samuel Villarreal and documented by Fabien Sanglard. This implementation is independent and contains no id Software code or assets.
